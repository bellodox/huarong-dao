## Commands and configuration
- “Ship”, “release”, and “next beta patch” mean local preparation/validation/review, never deployment. Do not run cloud authentication/status probes, login, remote publishing, commit/tag/push without explicit authorization. Cloud authentication is not a local-play prerequisite.
- Normal operator deployment is GitHub push → Workers Builds for bellodox/huarong-dao, currently production branch leaderboard, not local login/deploy or Pages. Follow the [dashboard settings](docs/cloudflare-deployment.md#2-primary-workflow-github-push-to-workers-builds); aggregate build regenerates both distributions before tests/deploy. Runtime secrets are separate from build variables, which do not sanitize remote bindings. No push/deployment authorization is implied.
- Use the actual [manifest](package.json), [lockfile](package-lock.json) and [local QA commands](README.md#available-local-qa-commands). All five existing Python Playwright suites now target the public asset; the deep suite independently BFS-checks all 14 layouts. All tests/check utilities belong under the root tests directory. There is no lint/typecheck/CI configuration; do not invent commands or infer style rules.
- [Wrangler](wrangler.jsonc) serves public assets, routes API paths Worker-first and schedules the [production publisher](leaderboard/publisher.js) every minute. Publication requires server-only ROD_APP_WIF, SUPABASE_URL, SUPABASE_SERVICE_KEY and HD1_RATE_HMAC_KEY plus fresh SQL readiness; WIF alone is insufficient. HD1_PUBLISHER=false disables it; HD1_READS=true permits optional reads. The retired issuer binding remains ignored; never inject keys into HTML.
- The [loopback fixture](tests/runtime-worker.js) is test-only, contains publicly known non-funded keys and must never be deployed. The [launcher](tests/runtime_servers.py) owns only its saved PIDs/loopback ports; stop them with its stop option. Do not kill unrelated processes. Disable dotenv loading for local fixture runs; never inspect restricted secret files.
